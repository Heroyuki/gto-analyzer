# ソルバーの精度評価と製品比較

- 更新・出典確認日: 2026-10-04
- 対象: 個人学習と、gto-analyzerへの将来のソルバー接続
- 状態: 理論・公式情報の整理。製品間の独自比較実験は未実施

## 1. ソルバーが計算するもの

ソルバーは、指定したレンジ・スタック・ボード・選択可能なアクション・評価条件の中で、均衡に近い戦略を計算する。ナッシュ均衡は、他のプレイヤーの戦略を固定したとき、自分だけ戦略を変えても利益を増やせない戦略の組合せを指す。

「GTO」と表示された解も、すべての実戦条件に対する万能な正解ではない。相手の入力レンジ、ベットサイズ、レーキ、チップEV／賞金EV等が変われば、計算対象そのものが変わる。LLMが文章で提案する戦略と、ソルバーが数値計算した戦略も区別する。

参考: [GTO Wizard: How Solvers Work](https://blog.gtowizard.com/how-solvers-work/)

## 2. 精度を3つに分ける

| 観点 | 確認すること | 例 |
| --- | --- | --- |
| 入力・評価条件の一致 | 知りたい局面を計算しているか | 相手のレンジ、スタック、レーキ、賞金条件が実際と違えば結果も変わる |
| モデルの細かさ | どんな選択肢・カード情報を考慮するか | ベット33%だけを許すツリーと、33%・75%・150%を許すツリーは別のゲーム |
| 計算の収束 | 指定したモデルの中で、どこまで均衡へ近づいたか | 途中で止めた計算と、十分に反復した計算の違い |

計算を長く続けても、誤った入力レンジや省略したアクションは自動で修正されない。また、ハンドや局面をまとめる「抽象化」で計算量を減らす場合、まとめた情報の違いは収束精度とは別に評価する必要がある。

参考: [GTO Wizard: How Solvers Work](https://blog.gtowizard.com/how-solvers-work/)、[MonkerSolver: Abstraction](https://monkerware.com/compare.html)

## 3. ExploitabilityとNash Distance

exploitabilityは、戦略につけ込まれる余地を測る代表的な指標。相手の戦略を固定し、こちらが最も有利な対抗戦略（best response）へ変えた場合に、どれだけEVを改善できるかを調べる。

ヘッズアップ・レーキなしのチップEVという2人ゼロ和ゲームでは、この値が小さいほど均衡に近いと考えられる。PioSOLVERが報告する指標は、両プレイヤーがbest responseへ変えた場合のEV改善量の平均である。

```text
Pioの報告値 = (OOPのEV改善量 + IPのEV改善量) / 2
```

製品ごとに名称・集計方法・分母・測定対象が違い得るので、数字だけを直接比較しない。レーキ、ICM、複数人数を含むゲームへ、2人ゼロ和ゲームの保証をそのまま当てはめない。大きなプリフロップ計算では、厳密なbest responseではなく、サンプリングや戦略変化による収束推定を使う場合もある。

参考: [PioSOLVER: Meaning of numbers](https://piosolver.com/docs/viewer/numbers_in_piosolver/)、[GTO Wizard: How Solvers Work](https://blog.gtowizard.com/how-solvers-work/)

### 数値の読み方

説明用の仮定として、開始ポット100bbに対して指標が0.1% potなら、bbへの換算は次のとおり。

```text
100bb × 0.001 = 0.1bb
```

これは「正解率99.9%」でも「各ハンドで必ず0.1bb損する」でもない。測定対象のレンジ・ツリーに対する集計指標であり、ツリーにないベットサイズまで保証しない。実戦の相手が最適な対抗戦略を使うという意味でもない。

## 4. 頻度の違いだけで精度を決めない

ある製品がベット60%、別の製品が55%と表示しても、それだけでは優劣を判断できない。まず入力条件、アクション、頻度の集計方法、収束条件を揃える。

均衡で複数のアクションを混ぜるハンドでは、それらのアクションのEVは等しくなる。ただし、頻度を任意に変えてよいという意味ではない。相手が対抗戦略を変えた場合の影響もあるため、比較にはEVとbest responseの評価が必要になる。

また、AA・AKs等の169分類の表示は、スート別コンボの情報をまとめている。ボード上のカード、ブロッカー、各コンボの重みを揃えずに分類別頻度を比較しない。全体頻度についても、単純なコンボ平均と相手のカード除去を考慮した頻度を区別する。

参考: [PioSOLVER: Calculation, strategies and other concepts](https://piosolver.com/docs/faq/gto_concept/)

## 5. GTO Wizardと従来型ソルバー

PioSOLVER等では、レンジとベットツリーを設定し、反復計算で戦略を求める。GTO Wizardには事前計算された解の閲覧と、条件を指定するカスタム計算の両方がある。

GTO Wizard AIのカスタム計算は、従来の計算方法と将来の局面の価値を予測する専用ニューラルネットワークを組み合わせる。この「AI」は、ChatGPTへ戦略の文章生成を依頼する方式とは異なる。

### メーカー公表のベンチマーク

GTO Wizardの公式記事は、2025年4月更新のエンジンについて、フロップの平均exploitabilityが開始ポットの約0.12%になったと報告している。記事の初版は2023年だが、後年の更新を含むため、初版の日付と測定対象の版を区別する。

公式記事の測定方法は、主にフロップ戦略を従来型ソルバーへ取り込み、片方の戦略を固定して、対抗戦略によるEV損失を測るもの。未来のストリート全体を固定して比較した値ではない。この数値を全局面の精度保証や、WASM Postflopとの差の数値として扱わない。

これはメーカーの公表値であり、このリポジトリで再現した結果ではない。現時点で「WASM PostflopはWizardより何%劣る」「Pioが常に最も正確」とは評価していない。

参考: [GTO Wizard AI Benchmarks](https://blog.gtowizard.com/gto-wizard-ai-benchmarks/)

## 7. AGPLと個人利用

WASM / Desktop PostflopとそのエンジンはAGPL-3.0を採用している。自分のPCで個人的に使う場合、通常はソースを一般公開する必要はない。改造版を他の人へ配布したり、ネットワーク経由で利用させたりする場合は、対応するソースコードの提供等の条件が関係する。

組み込み方によっては自作アプリ側にもライセンスの条件が及ぶため、「ソルバー部分だけ公開すれば常に十分」とは判断しない。ソース提供の条件は、履歴・個人情報・APIキーの公開を要求するものではない。

参考: [GNU AGPL第13条](https://www.gnu.org/licenses/agpl.en.html)、[GNUライセンスFAQ](https://www.gnu.org/licenses/gpl-faq.html)

## 8. 今後の学習・検証手順

最初は「2人・リバー・レーキなし・チップEV」の小さな局面から始める。これは学習順序の提案であり、全体のMTT実装範囲を縮小する決定ではない。

1. 両者のレンジ、ボード、ポット、残りスタック、許可するベット／レイズを記録する。
2. 無料ソルバーで計算し、反復量を増やした場合のEV・頻度・exploitabilityの変化を観察する。
3. レンジだけ、またはベットサイズだけを変え、モデルが変わる場合と収束が進む場合を区別する。
4. 同じ条件を別製品でも計算し、双方のEVの定義と指標の集計方法を揃えて比較する。
5. 可能なら外部エンジンによるbest responseも計算し、頻度の見た目だけで精度を判断しない。
6. リバーの検証ができてからターン・フロップへ拡張する。MTTの賞金EV／ICMは別の入力・モデルとして学ぶ。

### 比較実験で残す記録

| 項目 | 内容 |
| --- | --- |
| 計算対象 | ゲーム形式、人数、ストリート、ボード、レンジと各コンボの重み |
| 評価条件 | ポット、スタック、レーキ、チップEV／賞金EV、必要なら賞金表・残存スタック |
| ツリー | 全ストリートのサイズ、レイズ上限、all-in設定、抽象化・省略条件 |
| 実行環境 | エンジンの版・コミット、CPU、メモリー、スレッド数、時間、反復数 |
| 停止条件 | 収束指標、閾値、単位、分母、厳密計算か推定か |
| 出力 | レンジ全体EV、コンボ別EVと頻度、exploitability、外部評価の有無 |
| 根拠・限界 | メーカー公表値か独自測定か、再現可能性、比較できなかった条件 |

現在の学習画面には、両者の完全なレンジとベットツリーを設定する機能も、ソルバー実行もない。カード・ポット・スタックだけで実戦に対応したGTO頻度を自動生成できるとは扱わない。接続後も、説明用サンプル、ユーザー持込結果、条件と精度を記録して検証した結果を区別する。
