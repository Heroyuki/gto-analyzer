# ADR-0001: 新規アプリをTypeScriptに統一する

- 日付: 2026-09-27
- 状態: 採用
- 対象: 新規本番アプリの開発基盤。Python試作は参照用に残す。

## 背景

既存実装はPython/Streamlitのローカル試作であり、MTT、認証、アカウント分離、AWS構成は未実装。設計案はReact/TypeScriptとPythonバックエンドの混成だった。

## 判断

新規web/API/worker/parser/domainとCDKをTypeScriptで開発する。npm workspacesで管理し、APIと非同期ジョブの契約を `packages/contracts` に置く。開発・CIはNode.js 22で揃える。Lambdaランタイムとバンドル方法はインフラ実装時に対応状況を確認して確定する。

既存コード・テスト・依存定義は `legacy/python` に保存し、独立して実行可能にする。今回の作業では試作機能の移植、React画面、AWSリソース、LLM呼び出しを実装しない。

## 理由・注意点

フロントエンド、バックエンド、IaCで言語と契約型を共有し、仕様変更時の不一致を型検査で発見しやすくする。一方、型だけでは外部入力を検証できないため、HTTP・SQS・LLM応答の実行時検証は別途必要。

チップ計算に浮動小数点を使わない。安全整数を検証し、小数は十進文字列から最小単位へ変換する。bigintを使う場合はJSON表現を明示する。
Python試作の既知の制約（キャッシュ形式、ポット再構成不足、LLMをソルバーとして扱うプロンプト）をそのまま移植しない。

## 次の段階

匿名化した実MTT fixtureの入手と対応形式の仕様確定を先行し、その受入条件からTypeScriptパーサーを実装する。以降は[設計§14](../DESIGN.md#14-実装順序移行)に従う。
