# 要件定義

更新日: 2026-09-25

## 目的と確定事項

1. 既存のNotionのポーカー理論・学習資料を完成させる。
2. GG PokerのMTT履歴ファイルをアップロードし、ハンドレビューできるWebアプリケーションを開発する。
3. アカウントごとにデータを分離し、他のアカウントのデータを閲覧・操作できないようにする。
4. AWS上のサーバーレス構成とし、データベースにはDynamoDBを採用する。

## アプリケーションの初期仕様案

- ログイン後にGG PokerのMTT履歴テキストをアップロードする。
- 解析したハンドを一覧表示し、対象ハンドを選択できる。
- 手札、ボード、ポジション、スタック、アンティ、アクション、ポット推移を確認できる。
- レビューを非同期で実行し、処理状況と結果を表示する。
- 各判断の評価、推奨アクション、理由、改善点、関連するNotion学習資料を提示する。
- ICM評価に必要な大会情報が不足する場合は不足を明示する。追加入力の項目は別途定義する。
- GPTによる推論とソルバー等で計算した結果を区別し、未計算のEVや頻度を確定値として提示しない。

## AWS構成案

DB以外の個別サービスと詳細設定は設計時に確定する。

| 用途 | サービス案 |
| --- | --- |
| フロントエンド配信 | S3 + CloudFront |
| 認証 | Cognito |
| API | API Gateway + Lambda |
| ハンド、レビュー、ジョブの管理 | DynamoDB（オンデマンド） |
| 元の履歴ファイルの保存 | 非公開S3 |
| 非同期レビュー処理 | SQS + Lambda |
| APIキー管理 | Secrets Manager |

## アカウント分離の必須条件

- 履歴ファイル、解析済みハンド、レビュー結果、ジョブを所有者に紐付ける。
- 所有者IDは検証済み認証情報からサーバー側で取得し、クライアント指定のIDを認可の根拠にしない。
- 一覧、詳細、ダウンロード、更新、削除、レビュー実行と処理状況取得で所有者を確認する。
- 非同期処理でも所有者と処理対象の対応を維持する。
- S3ファイルを公開しない。署名付きURLを使う場合も発行前に所有者を確認する。
- 別アカウントでURLやデータIDを直接指定しても取得・変更できないことをテストする。

## 完了条件案

### Notion学習資料

- 対象ページと未完成箇所を棚卸しする。
- 対象ページに定義、前提、具体例、実戦への応用、出典を揃える。
- ハンドレビューから関連資料を参照できる。

### アプリケーション

- AWS環境でログインし、実際のGG Poker MTT履歴をアップロードできる。
- 対象ハンドを選び、局面とレビュー結果を確認できる。
- 不正な形式、情報不足、レビュー失敗をユーザーに表示する。
- アカウント間のアクセス拒否を確認する。

## 未確定事項

- Notion資料の対象範囲とページ別の完成基準。
- 実履歴のサンプルに基づく対応形式、ファイルサイズ、ハンド数の上限。
- DynamoDBのキーとインデックス設計（アカウント別一覧、ハンド詳細、レビュー履歴等）。
- レビューの評価基準、モデル、ソルバー利用範囲、追加の大会情報。
- 保存期間、削除仕様、利用上限、予算、AWSリージョン、認証方式。

## 現状

既存コードは `legacy/python/` に保存したStreamlitでの履歴解析・GPTレビューの試作。新規本番実装は[ADR-0001](architecture/decisions/0001-typescript.md)に従いTypeScriptに統一し、現在は開発基盤のみを整備済み。上記のAWS構成、認証、DynamoDBによる永続化が実装済みであることを意味しない。

## 学習画面のGit管理・AWS移行

2026-10-03追加: 現行のPoker Spot Visualizerを `Heroyuki/gto-analyzer` に取り込み、AWS上で動作確認できるようにする。まず設計を整備し、ローカル確認とAWS dev構築を段階的に行う。現行URLはOpenAI Sitesであり、AWS構築済みとは扱わない。詳細は[移行設計](architecture/POKER_SPOT_AWS.md)と[SPOT-001](specs/SPOT-001-visualizer.md)を参照する。

現行の所有者限定という共有意図を維持する。学習用の説明頻度をGTO計算結果と混同させない。AWSアカウント、検証環境の閲覧制限、予算などは設計案と確定事項を分けて管理する。
